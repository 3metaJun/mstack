### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record `df -h /`, then run `node "<meta-mode-tools>/worktree-audit.mjs" [-b <pr-base-ref>] [--fetch] [repo-path]` (the `.sh` name remains a compatibility wrapper) (principle-build-the-lever). Without `-b`, it checks `MERGED` against `origin/HEAD`, then `origin/main`, then `origin/master`. It writes nothing to the repository unless `--fetch` is passed, and sets `GIT_OPTIONAL_LOCKS=0` so it never collides with an active agent's index. It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `.harness/worktrees/myrepo/x` (principle-encode-lessons-in-structure). It classifies each worktree by size, age, merge state, uncommitted work, non-disposable ignored files, worktree-only reflog commits, locks, PR state, and the newest chat that touched it, then suggests a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar (on a host with native thread tracking, read `../references/hosts/` to also inspect active threads bound to worktrees) and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (principle-guard-the-context-window, transcripts are bulk). A pinned chat spawns arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar.
4. Pause on irreversible loss. `wip:N` is N tracked paths with uncommitted changes and `scratch:N` is N untracked paths. A worktree with multiple categories prints all of them, such as `wip:1,scratch:5`. `ignored:N` is N ignored paths outside the audit's `DISPOSABLE` build and cache directories (such as `.env` or local settings files), which may exist nowhere else. List them with `git -C <path> status --porcelain --untracked-files=normal --ignored=matching --ignore-submodules=none`, and when `.gitmodules` exists also run `git -C <path> submodule foreach --recursive 'git ls-files --others --ignored --exclude-standard --directory --no-empty-directory'`. `submodule:N` (`hold-submodule`) means N initialized or cached submodules exist under the worktree or `<worktree-gitdir>/modules/` (locate `<worktree-gitdir>` with `git -C <path> rev-parse --git-dir`); plain `git worktree remove` refuses linked worktrees while `<worktree-gitdir>/modules/` exists (even after `git submodule deinit`), and submodules default to detached HEAD whose commits can become reflog-only after a checkout or `submodule update`, so inspect commits with `git -C <path> submodule foreach --recursive 'git log --all --reflog --not --remotes --oneline'` and, for every module gitdir under `<worktree-gitdir>/modules/`, `git --git-dir=<module-gitdir> log --all --reflog --not --remotes --oneline`, then report those results and leave removal to the user rather than forcing deletion. `reflog:N` is N commits that no branch, tag, remote, or branch reflog reaches, kept only by the worktree's HEAD and HEAD reflog (such as work on a detached HEAD); keep any with `git branch <name> <sha>`. `unknown` (`hold-unknown`) means `git status` failed, so treat it as holding uncommitted work. `hold-locked` means another tool or agent locked the tree, with its reason in the `LOCKED` column. Show the status call above and the diff from `git -C <path> diff HEAD --ignore-submodules=none --submodule=log` and get a decision first. An empty diff never means nothing is at stake: a diff leaves out untracked files, and a plain `git diff` can miss submodule work. Delete user-approved untracked files only with `git --literal-pathspecs -C <path> clean -fd -- <file>...` so glob characters in filenames match literally. For a `prunable` worktree whose directory is gone, inspect `git log -1 worktrees/<id>/HEAD` and `git reflog show worktrees/<id>/HEAD` from the main checkout before removing it per path, never with a bulk prune. Per Autonomy, clean, unlocked, merged, and not-in-use proceeds. `wip`, `unknown`, `scratch`, `ignored`, `submodule`, `reflog`, `hold-locked`, and in-use pause.
5. Prune the confirmed set. Per path, run a plain `git worktree remove <path>`. It deletes every ignored file with the directory, and when `status.showUntrackedFiles=no` is set it also silently deletes untracked files, so a worktree with `scratch` or `ignored` waits for step 4's decision. It refuses a worktree with tracked edits, a lock, or populated/cached submodules (`<worktree-gitdir>/modules`), and that refusal is the stop: leave the worktree, report it (including step 4's submodule commit audit when submodules are present), and never add `--force` or delete the directory by hand with `rm -rf`. Branch refs survive, so commits on the worktree's branch are kept; the worktree's HEAD reflog goes with the worktree. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, the active Harness state directory and workspace snapshot cache, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, lock, or uncommitted/ignored/reflog work).
